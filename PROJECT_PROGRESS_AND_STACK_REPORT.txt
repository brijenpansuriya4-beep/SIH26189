1. SYSTEM OVERVIEW & PROBLEM STATEMENT
--------------------------------------------------------------------------------
The Crime Intelligence & Network Analysis Platform is an advanced software solution 
designed for intelligence agencies and law enforcement. It automates the parsing, 
link-analysis, and visualization of First Information Reports (FIRs) and raw intelligence 
texts. 

Core Objectives Solved:
* Automated Entity Extraction: Leveraging large language models (LLMs) to automatically 
  parse raw FIR narrative texts and extract crucial entities (Suspects, Phones, Locations, 
  Vehicles, and Bank Accounts).
* Network Visualization: Building dynamic, interactive 2D graphs mapping links between 
  extracted entities (such as "associated with", "uses phone number", or "spotted at location").
* Threat Scoring & Kingpin Detection: Using graph algorithms to score entities based on 
  their threat profiles and structural network centralities, highlighting primary kingpins.

3. DATABASE ARCHITECTURE & DATA FLOW
--------------------------------------------------------------------------------
The SQLite database file (crime_intel.db) is structured via database.py with the 
following schema layout:

* Model: User (Table: users)
  - id (Integer, Primary Key)
  - username (String, Unique, Index)
  - password_hash (String)
  - role (String, default: "Investigator")

* Model: FIRRecord (Table: fir_records)
  - id (Integer, Primary Key)
  - title (String)
  - text_content (Text)
  - created_at (DateTime)
  - created_by (Integer, Foreign Key to users.id)

* Model: Entity (Table: entities)
  - id (Integer, Primary Key)
  - name (String)
  - entity_type (String) -> Person, Phone, Location, Vehicle, Bank Account
  - threat_score (Float) -> Base threat/risk score (0.0 to 10.0)
  - fir_id (Integer, Foreign Key to fir_records.id)

* Model: Relationship (Table: relationships)
  - id (Integer, Primary Key)
  - source_id (Integer, Foreign Key to entities.id)
  - target_id (Integer, Foreign Key to entities.id)
  - relation_type (String) -> "related_to", "accomplice of", "coordinates with", etc.

Real-time Pipeline Flow:
[Raw FIR Input]
       │ (User submits raw FIR text in Frontend sidebar)
       ▼
[Groq LLM Parser]
       │ (ai_service.py parses text, mapping to entities & relationships JSON)
       ▼
[Database Commit]
       │ (main.py deduplicates node names, inserts new entities/edges to DB)
       ▼
[Dynamic React Graph Update]
         (Axios fetches new DB graph state; react-force-graph-2d updates in real-time)


4. COMPLETED FEATURES & IMPLEMENTATION STATE
--------------------------------------------------------------------------------
* Dynamic 2D Force Graph: Displays node networks using canvas rendering. Features custom 
  color coding per entity type, dynamic glow/shadow effects, tooltips, drag capability, 
  and automatic zoom-to-fit coordinates.
* AI-Powered Entity & Relationship Extraction: Robust parsing using the Groq LLM API. 
  It features an automatic local mock-data fallback if the API key is missing or 
  exhausted, preventing app crashes.
* Automated Threat Scoring: Ranks suspect prominence using graph centrality algorithms.
  - Threat Score Formula: (Base Risk * 0.4) + (Degree Centrality * 3.0) + (Betweenness Centrality * 3.0)
* Interactive Node Dossier: Displays a floating details panel populated with system metadata 
  (Entity type, system ID, risk) when a node is clicked.
* Multi-Frontend Consolidation Status: Current system is fully consolidated into a single 
  unified repository. Citizen reporting and investigator tip-off modules are in 
  planning stages for integration into the main UI command center panel.
